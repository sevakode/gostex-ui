# On-demand cover search

Open a game's hold menu → Cover → Find cover options. SteamGridDB first asks the owner to identify the correct game/edition, then shows up to 16 images, preferring landscape images. The saved **Prefer landscape covers** option (enabled by default) first asks SteamGridDB specifically for static 920×430 / 460×215 grids, falling back to the ordinary image list if none are available. Disabling it requests all shapes. This avoids losing suitable wide images behind the first page of portrait results. Moving focus requests only one debounced preview; confirming saves that image as the game's protected manual cover. Back returns to the cover editor and then to the original tile. The search title is editable without changing the library/ROM title.

Settings → Media and library → Game covers → Online sources and priority offers either order, either provider alone, or disabled. The saved choice is in `SharedPreferences("orbit")` as `covers.onlineSources`; old/unknown values have a safe default. There is no automatic network search when browsing Home, entering Library or importing a ROM. Failed/missing providers advance sequentially in the configured order; an empty SteamGridDB image result advances to the next available provider. Other source is available explicitly. Nothing overwrites an existing image until the owner confirms a choice.

SteamGridDB uses its supported API v2. Create a personal API key at https://www.steamgriddb.com/profile/preferences/api and enter it in Game covers → SteamGridDB API key, or directly in the search dialog. The key is masked, stored only in private orbit preferences, omitted from library exports and never sent to image CDN requests or logged. A blank value removes it. Without a key SteamGridDB is skipped with a visible explanation. No shared/developer key is embedded. The owner supplied a personal key for the 0.28.0 verification; the credential itself is not part of source, exports or reports.

Libretro works without credentials. A build-time, compressed filename index covers 16 supported consoles (59,140 image filenames, 929,708 compressed bytes in the 2026-11-04 snapshot). Only the chosen console's index is opened, inside the search coroutine, and exact normalized-title lookup yields regional variants. The launcher never downloads/parses a large HTML directory. It downloads only the focused preview/confirmed image from the original HTTPS thumbnail server. This index contains filenames, not the pictures. Source URLs, generation time and checksums are in `app/src/main/assets/libretro-covers/manifest.json`. Refresh it with `python3 native-launcher/tools/update_libretro_cover_index.py` when preparing an app update. Newly added provider files after that snapshot may require a later snapshot; manual image import remains available.

ScreenScraper is not connected in this release: it requires separate application developer access. No unsupported scraping or borrowed credentials are substituted.

The picker owns its client and closes/disconnects it when dismissed or when the Activity stops. Coroutine checkpoints, bounded response/image sizes, connect/read deadlines and a 180 ms preview debounce limit work. No WebView, external image loader, service, worker, startup hook or new dependency is added. Temporary image/API cache is capped at 24 MiB / 128 files, with atomic writes and fixed expiry; saved cover files reuse the existing 128 MiB managed store and 32 MiB decoded-artwork cache. A decode/checksum/storage failure retains the old selected cover. Private cover choice/index commits remain atomic.

Saved online images retain provider, uploader (where supplied) and source page, visible in the cover editor and exported as `selectedCredit` for a manual selection. Those fields are attribution to the uploaded artwork, not a claim that the uploader owns the original game's art. Shared-folder agent updates continue to respect manual override.

References checked during implementation: SteamGridDB's own Node client and API contracts at https://github.com/SteamGridDB/node-steamgriddb and https://www.steamgriddb.com/api/v2; Libretro's thumbnail guide at https://docs.libretro.com/guides/roms-playlists-thumbnails/ and the provider's actual console directories. Limits and device evidence are in `.reports/covers31/` at workspace level.

## Restored-library comparison (0.28.0)

The 71 non-demo reference titles were checked with authenticated requests: 58 had conservative exact-title SteamGridDB matches, 55 had landscape artwork, and 7 searches had ambiguous editions/names. The compact Libretro index resolved 62 titles. These numbers describe availability and shape, not an artistic-quality ranking or guaranteed platform match; the owner still chooses the correct edition and image. Both sources remain useful, with SteamGridDB first and Libretro as fallback. Sample inspection found that the first wide image can be a cartridge photograph or plain logo, so no bulk overwrite was performed. Evidence: `../../.reports/restore32/source-comparison.json`.

On-device 0.28.0 verification confirmed the masked key saved on Shield, authenticated title/edition results, landscape previews and a manual Castlevania save. Grid 104173 is retained with its SteamGridDB page and Supreme Ricardo attribution in `selectedCredit`. Device evidence: `../../.reports/restore32/device-checks.json`.
